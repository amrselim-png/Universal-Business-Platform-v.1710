# اختبارات End-to-End (E2E) — دليل التشغيل

> **الحالة:** الإعداد جاهز في المستودع، لكنه **يحتاج متصفحاً** — لا يعمل داخل بيئات CI المقيّدة.

---

## التشغيل على جهازك

```powershell
# 1) نزّل المتصفح (مرة واحدة — ~120 ميجا)
npx playwright install --with-deps chromium

# 2) ابنِ التطبيق (الاختبار يشتغل على نسخة الإنتاج لا التطوير)
npm run build

# 3) شغّل الاختبارات
npm run e2e
```

**المتوقع:**
```
  3 passed
```

---

## الاختبارات الحالية

| # | الاختبار | ما يتحقق منه |
|---|---|---|
| 1 | الصفحة تُحمَّل بلا أخطاء قاتلة | لا انهيار JS · `#root` مُصيَّر · لا فشل تحميل chunks |
| 2 | شاشة الدخول + تسجيل الدخول | الدخول بـ `admin`/`admin123` يوصل للتطبيق |
| 3 | محرك الشاشات محمَّل | كاش الـ Metadata صالح في `localStorage` |

**أخطاء يعتبرها الاختبار «قاتلة»:**
- `Failed to fetch dynamically imported module` (فشل تحميل شاشة مؤجّلة)
- `ChunkLoadError`
- `Cannot read property …`
- `is not a function`

---

## ⚠️ لماذا لا يعمل داخل هذا الساندبوكس؟

Chromium يحتاج مكتبات نظام (`libglib-2.0.so.0` وغيرها) وتركيبها يحتاج صلاحية root.
الخطأ الفعلي:
```
chrome-headless-shell: error while loading shared libraries:
libglib-2.0.so.0: cannot open shared object file
```

**الحل:** شغّله على جهازك بأمر `npx playwright install --with-deps chromium` (بيحمّل المكتبات تلقائياً).

## البديل الذي يعمل بلا متصفح

`src/__tests__/moduleIntegrity.test.ts` — 7 اختبارات تكامل تعمل داخل `npm run test`:

| الاختبار | ما يكشفه |
|---|---|
| كل شاشة تُصدِّر مكوّناً بنفس اسم الملف | شاشة بدون تصدير صحيح ⇒ **شاشة بيضاء** |
| كل استيراد في `App.tsx` يشير لملف موجود | مسار خاطئ بعد التقسيم |
| كل شاشة مؤجّلة في `lazyViews.ts` موجودة | `lazy()` يشير لملف محذوف |
| لا استيرادات مباشرة للشاشات في `App.tsx` | **رجوع الحزمة لحجم واحد ضخم** |
| لا ملفات مصدر فارغة | ملف فُقد محتواه |
| لا علامات تعارض دمج متبقية | `<<<<<<<` تسرّبت من merge |
