## 4️⃣ ⚠️ الخطر الوحيد — اقرأه قبل ما تفعّل الـ API

**دي أهم حاجة في الدليل كله.**

التطبيق بيشتغل افتراضيًا على **الاتصال المباشر** بقاعدة البيانات (الطريقة القديمة).
الـ API **اختياري** — بيتفعّل لما تحدد `erp_api_url`.

### 🔴 لو فعّلت الـ API:

فحص الصلاحيات بقى مفروضًا على السيرفر، والسيرفر بيفحص أكواد زي:
`record.save` · `record.delete` · `journal.post` · `receipt.create`

**لكن** أكواد الأفعال المسجّلة عند المستخدمين الحاليين **مختلفة تمامًا**:

| المستخدم | عنده | السيرفر بيطلب | النتيجة |
|---|---|---|---|
| `admin` | `['*']` | أي فعل | ✅ **يشتغل** |
| `cairo.mgr` | `pos.checkout`, `pos.discount`, … | `record.save` | ❌ **403** |
| `cashier1` | `pos.checkout`, `pos.print` | `record.save` | ❌ **403** |
| `accountant` | `accounting.add_entry`, … | `journal.post` | ❌ **403** |
| `dr.tarek` | `clinics.add_patient`, … | `record.save` | ❌ **403** |

### 👉 الحل المؤقت

**للتجربة دلوقتي: استخدم المستخدم `admin` بس** — عنده `['*']` فكل حاجة بتشتغل.

**قبل النشر للإنتاج:** لازم نوحّد أكواد الأفعال بين العميل والسيرفر (موجود في قائمة الناقص).

> 💡 **ملاحظة مطمِّنة:** لو مش فعّلت الـ API (الوضع الافتراضي)، **الخطر ده غير موجود** — كل حاجة شغالة زي الأول.

## 5️⃣ تشغيل الـ Migrations (اختياري لكن مستحسن)

لو عايز تجرّب **كل** المميزات:

